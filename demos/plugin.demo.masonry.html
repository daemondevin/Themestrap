01

3-column masonry — mixed-height items

columns: 3 · gutter: 16
card A

Typography

Line length, leading, and scale form the three pillars of readable type. A comfortable measure runs between 45 and 75 characters per line.

card B

Colour

HSL is the more intuitive workspace for building palettes.

card C

Grid systems

A grid is a scaffold, not a cage. Establishing a spatial system early lets every element occupy its correct proportion of the surface, keeping the layout coherent as content grows.

card D

Motion

Animation should communicate, not decorate. Ease-in-out curves for elements moving across the viewport; ease-out for elements entering; ease-in for elements leaving.

card E

Contrast

WCAG AA requires 4.5:1 for normal text.

card F

Spacing

An 8-point spacing scale keeps alignment decisions consistent across breakpoints. Multiples of 8 — 8, 16, 24, 32, 48 — cover most layout needs without bespoke values.

card G

Iconography

Keep icon strokes consistent. Match the weight of the surrounding text.

card H

Elevation

Shadows communicate z-axis position. Prefer layered box-shadows with low opacity over heavy single-shadow values — they appear more natural and work better in dark mode.

card I

Border radius

Keep border-radius consistent across components. A token-based approach guarantees that cards, buttons, and inputs share the same visual language.

$('#my-grid').themestrapPluginMasonry({
  columns:    3,       // number of columns
  gutter:     16,      // px gap between items
  itemsClass: '.masonry-item',
  animate:    true,   // fade-in on layout
});
// masonry layout complete
02

2-column — wider items, larger gutter

columns: 2 · gutter: 24
entry 1

Performance budgets

Set a budget before writing a line of code. Time-to-interactive under 3 s on a mid-range device over a simulated 4G connection is a reasonable starting point for most consumer-facing products.

entry 2

Accessibility first

Semantic HTML is the foundation. ARIA is a patch for when semantics fall short — prefer native elements wherever they exist.

entry 3

Progressive enhancement

Start with HTML that works without JavaScript, then layer interactivity. A broken JS bundle should never leave the user staring at a blank page.

entry 4

Core Web Vitals

LCP, INP, and CLS are the three metrics Google uses to measure page experience. Optimizing for them usually means optimizing for users.

entry 5

Caching strategy

Cache aggressively at the CDN level; invalidate with content hashes. Never serve stale HTML.

entry 6

Error boundaries

Every async operation that touches the network should have an explicit error state. Silence is a poor error message — show users something actionable when things go wrong, and log the error for diagnostics.

$('#msn-02').themestrapPluginMasonry({
  columns:    2,
  gutter:     24,
  itemsClass: '.masonry-item',
});
// 2-column layout ready

const msn = $('#msn-03').data('__masonry');

// append new element, then repack
$('#msn-03').append(newItem);
