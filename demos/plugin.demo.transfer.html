Themestrap component

PluginTransfer

Live progress for downloads, uploads, file copies and other long jobs. It shows bytes done and total, a smoothed speed, time left, job states, an indeterminate mode and an optional cancel button.

It has no vendor dependencies. The plugin builds its own markup and injects its CSS once, on first use. Any part with nothing to show hides itself, so the same element works as a single bar or a full status block.

<div id="demo-download" data-plugin-transfer
     data-plugin-options='{"label": "ubuntu-26.04.1-desktop-amd64.iso", "total": 6227886080, "cancelable": true}'></div>

Installation

  
    
    
  1. Copy themestrap.plugin.transfer.js to js/components/ and include it after themestrap.js.
    2. 
    
  2. Add the init block to themestrap.init.js. Initialize right away at DOM ready rather than through an IntersectionObserver. Producers call update() whether or not the element has scrolled into view, and an instance that doesn't exist yet would drop those updates. For the same reason, don't list it in themestrap.modules.js.
    3. 
  


// Transfer
if (typeof $.fn['themestrapPluginTransfer'] === 'function' && $('[data-plugin-transfer]').length) {
    $(() => {
        $('[data-plugin-transfer]:not(.manual)').each(function () {
            const $this = $(this);
            const opts  = themestrap.fn.getOptions($this.data('plugin-options')) || undefined;
            $this.themestrapPluginTransfer(opts);
        });
    });
}

  
Elements created later, or marked .manual, are initialized with $('#el').themestrapPluginTransfer({ … }).

Methods

  
Get the instance with $('#el').data('__pluginTransfer'). Every method except getInfo() returns the instance, so calls chain.

  

  

    
MethodDescription

    
      
update(done)
update(done, total)
update({ done, total, speed })		Report progress. Without speed, the speed is derived from successive calls. A smaller done (restart, next file) resets the speed sampling. Moves an idle or paused transfer to running.

      
setIndeterminate(bool)Unknown progress, e.g. verifying or waiting on a server. Turned off by the next update() with a known total.

      
setState(state, message?)idle, running, paused, done, failed or cancelled. done fills the bar and hides the cancel button. The message defaults to stateText[state].

      
setLabel(text)Change the heading.

      
setMessage(text)Change the message line. '' clears it.

      
getInfo(){ done, total, percent, speed, eta, state }

      
reset()Back to idle with zero bytes, keeping the options.

      
destroy()Remove handlers and restore the element's original markup and classes.

Theming

  
The defaults are declared with :where(.ts-transfer), which has zero specificity. A plain .ts-transfer { … } rule in your theme therefore wins, whatever the load order. When no token is set, colors fall back to Bootstrap's variables, so dark mode with data-bs-theme just works.

State classes on the root: .is-idle, .is-running, .is-paused, .is-done, .is-failed, .is-cancelled, plus .is-indeterminate and .is-unknown (running without a total). prefers-reduced-motion stops the animations.


  
Wiring to a real download


const t = $('#dl').themestrapPluginTransfer({ label: file.name, cancelable: true })[0];
const controller = new AbortController();
$('#dl').on('transfer:cancel', () => controller.abort());

const res = await fetch(url, { signal: controller.signal });
const total = Number(res.headers.get('Content-Length')) || null;
const reader = res.body.getReader();
let done = 0;
try {
    for (;;) {
        const { value, done: finished } = await reader.read();
        if (finished) break;
        done += value.length;
        t.update(done, total);
    }
    t.setState('done');
} catch (e) {
    t.setState(e.name === 'AbortError' ? 'cancelled' : 'failed', e.message);
}
