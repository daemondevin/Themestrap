PluginReadMore

ReadMore turns a long block into a compact card while preserving the original content in the DOM. The gradient overlay and toggle are created by the plugin.

Live article

Themestrap began with a simple premise: common interface behavior should be reusable without forcing a project into a build system, application framework, or large runtime. A website should be able to adopt the pieces of interaction it actually needs without having to restructure the entire project around them.

That makes small components surprisingly important. A tooltip can explain an unfamiliar control. A scroll affordance can make a long page easier to navigate. A loading overlay can provide feedback while an operation is taking place. A notification can confirm that an action succeeded. None of these features is particularly large on its own, but together they can transform an interface from something that merely functions into something that feels polished and intentional by design.

The less obvious benefit is composability. Themestrap components are designed to exist independently while still working naturally alongside one another. A component can be initialized from markup, configured through data attributes, and exposed through JavaScript when an application needs direct control. The same component can therefore live comfortably in a static HTML page, a CMS template, a server-rendered application, or a dynamically inserted fragment.

This approach also keeps responsibility where it belongs. A tooltip does not need to understand the application that contains it. A carousel does not need to manage the page around it. A loading indicator does not need to know how an API request is implemented. Each component provides a focused piece of behavior while leaving the surrounding application in control.

This demo deliberately combines the quieter components rather than presenting a gallery of conventional accordions, tabs, and modals. The intention is to demonstrate something closer to how these components are actually useful in a project: not as isolated attractions, but as small pieces that work together.

The result is an ordinary interface enhanced by a collection of purposeful details. Tooltips provide context, loading states communicate progress, scroll controls improve navigation, and other supporting components respond to the user's actions without demanding attention for themselves.

That is the role Themestrap is intended to fill. It is not necessary to turn every website into a full application simply because it needs a little interaction. Sometimes all a project needs are a handful of well-contained components that can be dropped into existing markup, configured when necessary, and controlled directly when the application calls for it.

The individual components may be small. Their ability to work together is what makes them useful. 

<div data-plugin-read-more
    data-plugin-options='{"overlayColor":"#ffffff","darkOverlayColor":"#111e2f","align":"center"}'>
    <p>...content...</p>
</div>

Magnetic controls

PluginHoverEffect

HoverEffect's magnetic mode needs no third-party hover library. Move the pointer around the control and the button follows the cursor slightly, then settles back when the pointer leaves. 

<button data-plugin-hover-effect 
    data-plugin-options='{"effect":"magnetic","magneticMx":0.12}'>
    Magnetic action
</button>

Motion that waits for the page

PluginAnimate

The Animate plugin adds the requested animation class and can coordinate with the loading overlay. This example uses a custom ts-rise animation so the plugin itself supplies the lifecycle while the page supplies the visual style.

Live

Observe Animation classes are applied by Themestrap.
Delay A second element can use its own delay attribute.
Compose The component does not need a framework-specific animation system. 
<div data-plugin-animate
     data-appear-animation="ts-rise"
     data-plugin-options='{"forceAnimation":true}'>
    Content
</div>

Randomized visual feed

PluginRandomImages

A wrapper can contain several images and RandomImages will rotate them. The demo uses inline SVG data images, so it remains self-contained and doesn't depend on an image CDN.

Rotating palette

rotating every 2.6 seconds 
<div data-plugin-random-images
    data-plugin-options='{"delay":2600,"random":true}'>
    <img ... />
    <img ... />
</div>

Runtime loading overlay

LoadingOverlay

This component can be shown and hidden around an asynchronous-looking operation. The demo intentionally waits two seconds so the overlay is easy to inspect.

Project synchronization Ready to simulate a network operation. 
const overlay = $('#overlay-stage').data('loadingOverlay');
overlay.show();
setTimeout(() => overlay.hide(), 2000);

Application notifications

PluginToast

Toast is useful as a fire-and-forget component: no permanent DOM node is required. Choose a message type below and Themestrap creates the appropriate container and Bootstrap toast instance.

Try each variant

themestrap.PluginToast.show({
    title: 'Synchronization complete',
    body: 'All field-kit modules are up to date.',
    type: 'success',
    position: 'top-end'
});
