# PluginLockscreen

A full-viewport PIN lockscreen overlay. Covers the page with a blurred, dimmed backdrop, displays a live clock, optional avatar and user name, and embeds a **PluginOtp** input for PIN entry. Failed attempts are tracked against a configurable limit; exceeding it enters a timed blocked state. An idle timer can lock the screen automatically after a period of inactivity, with an optional countdown badge in the corner.

All inner DOM — backdrop, card, clock, avatar, OTP input, buttons, attempt indicators — is generated by the plugin. CSS is injected lazily via `<style id="ts-lockscreen-styles">`.

> **Dependency:** `themestrap.plugin.otp.js` must be loaded before `themestrap.plugin.lockscreen.js`.

---

## Quick Start

### Include the plugins

```html
<!-- After jQuery and themestrap.js -->
<script src="js/components/themestrap.plugin.otp.js"></script>
<script src="js/components/themestrap.plugin.lockscreen.js"></script>
```

### Minimal markup

```html
<div id="page-lock"></div>
```

```js
$('#page-lock').themestrapPluginLockscreen({
    pin:  '1234',
    name: 'Alex Kim',
});

// Activate manually
$('#page-lock').data('__pluginLockscreen').lock();
```

### With data attributes

```html
<div data-plugin-lockscreen
     id="page-lock"
     data-plugin-options='{"pin":"1234","name":"Alex Kim","idleTimeout":300}'></div>
```

### Auto-init wiring (`themestrap.init.js`)

```js
if ($.isFunction($.fn['themestrapPluginLockscreen']) && $('[data-plugin-lockscreen]').length) {
    $(() => {
        $('[data-plugin-lockscreen]:not(.manual)').each(function () {
            const $this = $(this);
            const opts  = themestrap.fn.getOptions($this.data('plugin-options')) || undefined;
            $this.themestrapPluginLockscreen(opts);
        });
    });
}
```

## Options

All options are merged as: `PluginLockscreen.defaults → JS opts argument → data-plugin-options JSON`. Later values win.

### Authentication

| Key | Type | Default | Description |
|---|---|---|---|
| `pin` | string | `"0000"` | Expected PIN. Compared as plain strings. Change at runtime via `setPin()`. |
| `pinLength` | number | `4` | Number of OTP boxes rendered. Passed to PluginOtp. |
| `pinType` | string | `"numeric"` | `"numeric"` or `"alphanumeric"`. Passed to PluginOtp. |

### Display

| Key | Type | Default | Description |
|---|---|---|---|
| `name` | string | `""` | User display name shown below the avatar. First letter used as initials if no avatar image is provided. |
| `avatar` | string | `""` | URL to an avatar image. If absent, the first letter of `name` is rendered in the avatar circle. |
| `message` | string | `"Enter your PIN to continue"` | Body copy shown below the name. |
| `use24h` | bool | `false` | Display the clock in 24-hour format. |
| `otpSize` | string | `""` | Size modifier passed to PluginOtp. `""` · `"sm"` · `"lg"`. |
| `showClear` | bool | `true` | Render a Clear button below the OTP input. |
| `submitLabel` | string | `"Unlock"` | Label on the primary unlock button. |
| `clearLabel` | string | `"Clear"` | Label on the clear button. |

### Attempt limiting

| Key | Type | Default | Description |
|---|---|---|---|
| `maxAttempts` | number | `5` | Maximum wrong-PIN attempts before the blocked state is entered. `0` = unlimited. |
| `blockDuration` | number | `30000` | Milliseconds to stay blocked after `maxAttempts` is reached. `0` = permanent until page reload. |
| `wrongPinMessage` | string | `"Incorrect PIN. Try again."` | Error shown in the OTP input on a failed attempt. |
| `shortPinMessage` | string | `"Please enter the full PIN."` | Error shown when the Unlock button is clicked before all boxes are filled. |
| `blockedMessage` | string | `"Too many incorrect attempts. Please wait."` | Copy shown in the blocked-state panel below the attempt dots. |

### Idle auto-lock

| Key | Type | Default | Description |
|---|---|---|---|
| `lockOnLoad` | bool | `false` | Activate the lockscreen immediately when the plugin initializes. |
| `idleTimeout` | number | `0` | Seconds of inactivity (no mouse, keyboard, or touch events) before the screen locks automatically. `0` disables the watcher entirely. |
| `showIdleBadge` | bool | `true` | Show a countdown pill fixed to the bottom-right corner of the viewport when the idle timer is active and 30 or fewer seconds remain. |

## Public API

### Accessing the instance

```js
// Initialize, then retrieve separately — do NOT chain .data() off the bridge return value
$('#page-lock').themestrapPluginLockscreen({ pin: '1234' });
const ls = $('#page-lock').data('__pluginLockscreen');
```

### Methods

| Method | Returns | Description |
|---|---|---|
| `lock()` | `this` | Activate the lockscreen. Adds `.ts-lock--active`, locks body scroll, clears and focuses the OTP input, dispatches `ts.lockscreen.locked`. No-op if already locked. |
| `unlock()` | `this` | Deactivate the lockscreen. Removes `.ts-lock--active`, restores body scroll, clears the OTP input. No PIN check — programmatic override. No-op if already unlocked. |
| `setPin(pin)` | `this` | Change the expected PIN at runtime. Takes effect on the next unlock attempt. |
| `isLocked()` | `bool` | Returns `true` if the lockscreen is currently active. |
| `resetAttempts()` | `this` | Clear the failed-attempt counter and the blocked state. Re-enables the OTP input and Unlock button. |
| `destroy()` | `this` | Full teardown — removes all generated DOM, clears intervals, removes the idle event listeners, restores body scroll, and removes the data key. |

## Events

All events are dispatched as native `CustomEvent` on the wrapper element with `bubbles: true`.

| Event | `detail` payload | When |
|---|---|---|
| `ts.lockscreen.locked` | — | The lockscreen becomes visible. |
| `ts.lockscreen.unlocked` | `{ enteredPin: string }` | The correct PIN is submitted and verified. Fired before the overlay is hidden. |
| `ts.lockscreen.failed` | `{ enteredPin: string, attempts: number }` | A wrong PIN is submitted. `attempts` is the running total since last reset. |
| `ts.lockscreen.blocked` | `{ attempts: number }` | The `maxAttempts` limit is reached and the blocked state is entered. |

```js
const $lock = $('#page-lock');

$lock.on('ts.lockscreen.locked', function () {
    console.log('screen locked');
});

$lock.on('ts.lockscreen.unlocked', function (e) {
    console.log('unlocked — entered PIN was:', e.detail.enteredPin);
});

$lock.on('ts.lockscreen.failed', function (e) {
    console.log('wrong PIN, attempt', e.detail.attempts);
});

$lock.on('ts.lockscreen.blocked', function (e) {
    console.log('blocked after', e.detail.attempts, 'attempts');
    notifyAdmin(); // optional server-side flag
});
```

#page-lock {

## Keyboard Navigation

| Key | Context | Action |
|---|---|---|
| Digit keys | OTP input boxes | Fill the current box and advance focus. |
| `Backspace` | OTP input boxes | Clear the current box or retreat to the previous. |
| `←` / `→` | OTP input boxes | Move focus between boxes. |
| `Home` / `End` | OTP input boxes | Jump to the first or last box. |
| `Enter` | Anywhere while locked | Submit the current OTP value (same as clicking Unlock). |
| `Escape` | Anywhere while locked | No-op — the lockscreen does not close on Escape. |
| `Tab` | While locked | Body scroll is locked; focus is contained within the lockscreen card by the browser's natural tab order through the rendered inputs and buttons. |

## Recipes

### Lock on page load

```js
$('#page-lock').themestrapPluginLockscreen({
    pin:        '5678',
    name:       'Jordan Reeves',
    lockOnLoad: true,
});
```

### Idle auto-lock with a 5-minute timeout

```js
$('#page-lock').themestrapPluginLockscreen({
    pin:          '1234',
    name:         'Sam Okafor',
    idleTimeout:  300,    // 5 minutes
    showIdleBadge: true,
});
```

### Lock when the user navigates away (Page Visibility API)

```js
$('#page-lock').themestrapPluginLockscreen({ pin: '9999', name: 'Guest' });
const ls = $('#page-lock').data('__pluginLockscreen');

document.addEventListener('visibilitychange', function () {
    if (document.hidden) ls.lock();
});
```

### Change the PIN at runtime (settings panel)

```js
$('#save-pin-btn').on('click', function () {
    const newPin = $('#pin-field').val().trim();
    if (newPin.length < 4) return;
    const ls = $('#page-lock').data('__pluginLockscreen');
    ls.setPin(newPin).resetAttempts();
    showToast('PIN updated');
});
```

### Notify the server on block

```js
$('#page-lock').on('ts.lockscreen.blocked', function (e) {
    fetch('/api/security/lockout', {
        method:  'POST',
        headers: { 'Content-Type': 'application/json' },
        body:    JSON.stringify({
            attempts:  e.detail.attempts,
            timestamp: Date.now(),
        }),
    });
});
```

### Unlimited attempts with a custom error message

```js
$('#page-lock').themestrapPluginLockscreen({
    pin:             '0000',
    maxAttempts:     0,                    // no limit
    wrongPinMessage: 'Not quite — try again.',
});
```

### 6-digit OTP mode (two-factor style)

```js
$('#page-lock').themestrapPluginLockscreen({
    pin:       '483920',
    pinLength:  6,
    otpSize:   'sm',
    message:   'Enter the code from your authenticator app.',
    showClear:  false,
    submitLabel: 'Verify',
});
```

### Programmatic lock/unlock via keyboard shortcut

```js
$('#page-lock').themestrapPluginLockscreen({ pin: '1234' });

$(document).on('keydown', function (e) {
    if (e.ctrlKey && e.key === 'l') {
        e.preventDefault();
        const ls = $('#page-lock').data('__pluginLockscreen');
        ls.isLocked() ? ls.unlock() : ls.lock();
    }
});
```

## Common Pitfalls

**Overlay appears but the OTP input is missing**
PluginOtp must be loaded before PluginLockscreen. The lockscreen checks for `themestrap.PluginOtp` at build time; if it is undefined the OTP segment is silently skipped and no input renders.

**Lockscreen is visible underneath other fixed elements (header, modal)**
The overlay uses `z-index: 2000`. If your layout has fixed elements with higher z-index values, raise the overlay: `#page-lock { z-index: 9999; }`. Note that `backdrop-filter` requires the element to establish a stacking context, so avoid setting `z-index: auto` on the parent.

**Body scroll not restored after `destroy()`**
`destroy()` calls `$('body').css('overflow', '')`. If another part of your code also sets `body { overflow: hidden }`, the lockscreen cannot know about it and will clear it. Coordinate body-scroll locking with a shared utility if multiple plugins touch it.

**Idle badge never appears**
The badge appears only when `showIdleBadge: true`, `idleTimeout > 0`, the screen is **not** locked, and the remaining idle time is ≤ 30 seconds. Verify those conditions. The badge element is appended to `<body>` — check for it with DevTools.

**`setPin()` does not take effect on the current locked screen**
`setPin()` updates `options.pin` immediately. The next call to `_verify()` (triggered by any unlock attempt) will compare against the new value. There is no need to unlock and relock; the change is live.

**`lockOnLoad: true` interferes with page focus / screen readers**
When `lockOnLoad` is true the OTP input receives focus before the page has fully rendered. On some screen reader + browser combinations this can cause the virtual cursor to skip the lockscreen. Wrap the init in a short `setTimeout(() => ls.lock(), 100)` after DOMReady if you encounter this.

**Blocked state does not clear after `blockDuration`**
`blockDuration: 0` means permanent until a page reload. Set it to a positive number (milliseconds) for a timed unblock. `resetAttempts()` overrides this immediately regardless of `blockDuration`.

**`ts.lockscreen.unlocked` fires before the overlay is hidden**
By design — the event fires first so you can run a transition or navigate before the overlay disappears. The overlay hides 220 ms later via `setTimeout`. If you need to act strictly after the overlay is gone, listen for the CSS transition end on the root element.

**Diagnostic checklist**

- Does `$('#page-lock').data('__pluginLockscreen')` return an instance (not `undefined`)? Chains like `.themestrapPluginLockscreen({...}).data('__pluginLockscreen')` return `undefined` because `.data()` is reading from the jQuery map return, not the DOM element. Separate init from retrieval.
- Is `themestrap.PluginOtp` defined at the time PluginLockscreen initializes? Load order: jQuery → themestrap.js → themestrap.plugin.otp.js → themestrap.plugin.lockscreen.js.
- Is the overlay element positioned `fixed` and does it span the full viewport? Check that no ancestor has `transform`, `filter`, or `will-change` — these create new containing blocks that break `position: fixed` descendants.
- Does `isLocked()` return `true` when the overlay is visible? If not, `lock()` was not called or returned early due to already being locked.
- Are events firing? Add a bare `$('#page-lock').on('ts.lockscreen.locked', () => console.log('locked'))` — if this doesn't fire, the event dispatch path is broken and the plugin likely didn't init correctly.
